[45] {1|-} ВВЕДЕНИЕ
[46] {-|-} В последние годы сервисы всё чаще интегрируются непосредственно в среду мессенджеров. Пользователи предпочитают получать услуги без установки дополнительных приложений и лишних переходов по внешним ссылкам. Этот запрос стимулирует развитие формата мини-приложений (Mini Apps) — веб-решений, работающих внутри интерфейса хост-платформ. Платформа MAX, занимающая устойчивые позиции в сегменте корпоративных коммуникаций, предоставляет разработчикам открытое API и инструменты для реализации таких проектов.
[47] {-|-} В сфере эзотерических услуг нумерология сохраняет стабильный спрос: расчёты по дате рождения и именным данным регулярно востребованы аудиторией, ориентированной на самопознание. Однако существующие цифровые решения в этой области ограничены двумя типами: чат-боты с линейным сценарием и веб-сайты, не адаптированные для мобильных экранов. Ни тот, ни другой формат не дают пользователю персонализированного, визуально проработанного и оперативного расчёта. Возникает разрыв между реальной потребностью и тем, что предлагает рынок. 
[48] {-|-} Таким образом, разработка мини-приложения для нумерологического сервиса в мессенджере MAX позволяет объединить сложные алгоритмы расчёта числовых матриц с современными стандартами интерфейса и высокой скоростью доступа к результату. Именно это обеспечивает актуальность данной работы. 
[49] {-|-} Практическая значимость работы заключается в использовании разработанного мини-приложения для коммерческого предоставления нумерологических услуг пользователям платформы MAX с возможностью оплаты полных разборов непосредственно внутри мессенджера. 
[50] {-|-} Элемент новизны заключается в том, что подобные сервисы в экосистеме MAX на момент написания работы отсутствуют, а разработанная структура интерфейса может служить шаблоном для других B2C-сервисов.
[51] {-|-} Объект исследования – процесс разработки и интеграции мини-приложений в экосистему мессенджера MAX.
[52] {-|-} Предмет исследования – архитектурные, алгоритмические и интерфейсные решения, применяемые при создании нумерологического сервиса в формате мини-приложения для платформы MAX.
[53] {-|-} Цель работы – разработать и внедрить мини-приложение для платформы MAX, обеспечивающее автоматизированный нумерологический расчёт с визуализацией результатов и интеграцией платёжного модуля.

[61] {1|-} 1 ТЕОРЕТИЧЕСКИЕ ОСНОВЫ РАЗРАБОТКИ МИНИ-ПРИЛОЖЕНИЙ ДЛЯ МЕССЕНДЖЕРОВ
[62] {2|-} Мини-приложения в структуре современных мессенджеров
[63] {-|-} Современный рынок цифровых продуктов характеризуется смещением фокуса с мобильных приложений в сторону интеграционных решений, встроенных в экосистемы мессенджеров. Наиболее ярким проявлением данного тренда являются мини-приложения (Mini Apps) — адаптированные веб-страницы, функционирующие непосредственно внутри интерфейса хост-платформы без необходимости загрузки из магазинов приложений [1]. 
[64] {-|-} Мини-приложение представляет собой веб-решение, использующее нативные возможности платформы. Создание веб-интерфейса, интегрированного через API, обходится дешевле и выполняется быстрее, чем разработка двух платформенных версий нативного ПО (iOS и Android). При этом доступ к функционалу осуществляется мгновенно, без установки и ручного обновления, что обеспечивает бесшовный пользовательский опыт [1].
[65] {-|-} Функциональный потенциал Mini Apps практически не ограничен: платформа позволяет реализовать интернет-магазин с оформлением заказа, систему бронирования, сервис доставки, интерактивные игры, обучающие платформы, инструменты сбора обратной связи, публикацию контента, а также полноценный личный кабинет клиента — и всё это непосредственно в среде MAX. Такой подход позволяет минимизировать барьеры при взаимодействии, оптимизировать клиентский путь и сформировать дополнительные каналы для продаж и маркетинговых коммуникаций. Mini Apps функционируют в защищённом веб-пространстве, а доступ к персональным данным пользователя строго регламентирован через API MAX: разработчик получает доступ исключительно к той информации, на обработку которой пользователь предоставил явное согласие [2].
[66] {2|-} Технологические и бизнес-возможности платформы MAX
[67] {-|-} Мессенджер MAX предоставляет разработчикам инфраструктуру для создания мини-приложений, интегрированных в корпоративную среду платформы. В отличие от Telegram и VK, ориентированных преимущественно на массовую потребительскую аудиторию, MAX нацелен на бизнес-сегмент: его пользователями являются сотрудники компаний, что формирует платёжеспособную и вовлечённую аудиторию для B2C-сервисов [2]. 
[68] {-|-} Технически мини-приложение в MAX представляет собой веб-приложение, загружаемое через WebView. Платформа предоставляет стандартизированное API для авторизации (пользователь входит в приложение через MAX ID без повторного ввода данных), отправки сообщений, доступа к профилю и интеграции с внешними сервисами. Это позволяет разработчику сосредоточиться на бизнес-логике, не реализуя базовые функции аутентификации и коммуникации с нуля [2].
[69] {-|-} С точки зрения безопасности, доступ к данным пользователя строго регламентирован: приложение получает только ту информацию, на обработку которой пользователь дал явное согласие. Все запросы проходят через официальное API MAX, что исключает несанкционированный доступ и соответствует требованиям законодательства о защите данных. Важной особенностью платформы является встроенная экосистема платежей. MAX поддерживает интеграцию с платёжными шлюзами, что позволяет организовать приём оплаты за платные услуги без выхода пользователя из мессенджера. Это важно для коммерческих сервисов: пользователь оплачивает полный разбор в два касания, не переходя на внешний сайт и не вводя платёжные данные повторно [2].
[70] {2|-} Специфика разработки нумерологического сервиса в формате мини-приложения
[71] {-|-} Нумерологический сервис требует точных расчётов, персонализированной интерпретации и наглядной подачи результатов. Формат мини-приложения для MAX решает эти задачи эффективнее, чем чат-бот или веб-сайт. Сбор данных в мини-приложении организован через графические элементы: календарь для даты рождения, кнопки выбора пола, поле с валидацией имени. Это удобнее текстового диалога в чат-боте и снижает количество ошибок при вводе. Результаты выводятся структурированно — ключевые числа отдельными блоками с заголовками и описаниями, тогда как чат-бот выдаёт сплошной текст, который сложно воспринимать на экране телефона [3].
[72] {2|-} Особенности проектирования пользовательских интерфейсов для мини-приложений мессенджеров
[73] {-|-} Качество пользовательского интерфейса и опыта во многом определяет успех мини-приложения. Проектирование интерфейсов для мини-приложений имеет ряд отличий от веб-сайтов и нативных приложений, обусловленных спецификой среды и сценариями использования. Пользователь открывает мини-приложение внутри мессенджера, где его внимание постоянно переключается между чатами и уведомлениями. В отличие от браузера с множеством вкладок, мини-приложение работает в модальном окне поверх интерфейса платформы. Навигация должна быть линейной и предсказуемой: кнопка возврата ведёт на предыдущий экран внутри приложения, а не закрывает его [4].
[74] {-|-} Мини-приложения открываются на мобильных устройствах с небольшими экранами (6–7 дюймов), поэтому все элементы управления должны быть крупными (не менее 44 pt для сенсорных целей), текст — читаемым без масштабирования, информационная нагрузка на один экран — минимальной. Избыточность приводит к быстрому уходу пользователя: в мессенджере он привык к быстрым и коротким взаимодействиям [4].
[75] {-|-} Скорость загрузки — критический параметр. 53% пользователей покидают сайт при загрузке дольше 3 секунд. Для мини-приложений порог ещё ниже, поскольку пользователь воспринимает его как часть мессенджера и ожидает мгновенной реакции. Это требует оптимизации ресурсов: сжатия изображений, минификации кода, минимизации HTTP-запросов [4].
[76] {2|-} Теория когнитивной нагрузки применительно к мини-приложениям
[77] {-|-} При проектировании интерфейсов для нумерологических сервисов важно учитывать когнитивную нагрузку пользователя. Согласно теории Джона Свеллера, объём информации, который человек может одновременно удерживать в рабочей памяти, ограничен (7 ± 2 элемента). В мини-приложении, где пользователь отвлекается на уведомления мессенджера, этот объём сокращается до 3–4 элементов. Это означает, что нумерологические данные нельзя выводить на один экран — пользователь не успеет их осмыслить. Информацию следует подавать поэтапно: сначала ключевые числа (число личности, число реализации, число отношений), затем их расшифровка, и только потом дополнительные детали. Такой пошаговый подход позволяет удерживать внимание и даёт время на осмысление каждого блока [5].
[78] {-|-} Снизить когнитивную нагрузку помогает и визуализация. Графическое представление данных (например, цветовые блоки или карточки) воспринимается быстрее текста: исследования показывают, что визуальная информация обрабатывается мозгом в 60 000 раз быстрее. В контексте нумерологического сервиса это означает, что ключевые числа лучше выносить в отдельные карточки с цветовыми акцентами [5].

[129] {-|-} Проведённый анализ позволяет выделить несколько ключевых отличий разрабатываемого решения от существующих аналогов. Прежде всего, ни один из рассмотренных сервисов не предоставляет услугу в формате мини-приложения внутри мессенджера. Numera AI и Predskazanie.ru требуют перехода на веб-сайт через браузер, что в мобильном сценарии добавляет несколько дополнительных действий. Установка нативного приложения Numerology AI Compatibility занимает время и место на устройстве, а также требует отдельной авторизации. Разрабатываемое мини-приложение открывается внутри мессенджера MAX в один клик, использует авторизацию через MAX ID и не требует установки. Это кардинально сокращает путь пользователя к сервису и соответствует поведенческому паттерну пользователей мессенджеров.
[130] {-|-} В области монетизации конкуренты используют либо подписочную модель с высоким порогом входа (от 560 рублей в месяц у Numerology AI), либо разовые пакеты, не дающие полного доступа ко всем функциям (Numera AI), либо рекламную модель с низким качеством персонализации (Predskazanie.ru). Разрабатываемое приложение предлагает точечную оплату за конкретный результат: 119 рублей за полный личный разбор и 149 рублей за разбор пары. Это дешевле подписки у конкурентов, при этом пользователь получает персонализированный AI-отчёт, который остаётся у него навсегда, без ежемесячных списаний.
[131] {-|-} Отдельного внимания заслуживает использование искусственного интеллекта. Numera AI и Numerology AI активно используют AI для персонализации и создания «живого» опыта общения: в первом случае это ИИ-чат, учитывающий историю запросов, во втором — создание AI-модели личности, с которой можно вести диалог. Разрабатываемое приложение использует GigaChat для генерации платных отчётов, что соответствует рыночному тренду, но в отличие от конкурентов AI применяется не для интерактивного диалога, а для улучшения качества текстов расшифровок. Это направление может быть развито в будущем — например, добавление AI-чата для быстрых вопросов.
[132] {-|-} Качество пользовательского интерфейса также различается. Numera AI выглядит современно и технологично, но его интерфейс воспринимается как холодный и стерильный. Numerology AI минималистичен, но не имеет уникальной визуальной идентичности. Predskazanie.ru визуально устарел и не адаптирован для мобильных экранов. Разрабатываемое приложение ориентировано на тёплую, эстетичную и мобильную эстетику: пастельные цвета, карточки с тенями, мягкие формы, чистая типографика. Это создаёт нужную для эзотерического сервиса атмосферу и повышает доверие пользователя.
[133] {-|-} Важным конкурентным преимуществом является доступ к аудитории MAX. В отличие от конкурентов, ориентированных на массовый B2C-сегмент, разрабатываемое приложение через платформу MAX получает доступ к платёжеспособным пользователям из бизнес-среды — сотрудникам компаний, которые используют MAX как рабочий инструмент. Кроме того, на момент написания работы в экосистеме MAX отсутствуют аналогичные эзотерические сервисы, что даёт проекту статус одного из первых в этом сегменте.
[134] {-|-} Таким образом, анализ конкурентов показывает, что основными преимуществами разрабатываемого мини-приложения являются: бесшовная интеграция с экосистемой MAX, сокращённый путь пользователя к сервису, точечная модель оплаты без ежемесячных списаний, использование AI для улучшения качества отчётов и адаптированный под мобильные экраны эмоциональный дизайн. Рыночная ниша — платёжеспособные пользователи корпоративного мессенджера MAX, которым требуется быстрый и персонализированный нумерологический расчёт без выхода из привычной цифровой среды.

[142] {2|-} Общая характеристика приложения и постановка задачи
[143] {-|-} Мини-приложения (mini-app) — это компактные веб-приложения, работающие внутри мессенджера без отдельной установки; для бизнеса они позволяют предоставить сервис прямо в переписке. По устройству веб-аппы и мини-аппы представляют собой веб-страницы, которые загружаются и исполняются внутри приложения-хоста и получают от него данные о пользователе. Именно такой формат выбран для проекта [6, 7].
[144] {-|-} Практическая часть посвящена разработке mini-app для мессенджера MAX на основе готового чат-бота «Подружка», который по дате рождения формирует персональные разборы, определяет совместимость, выдаёт «совет дня» и предлагает платные отчёты. Единая дизайн-система (цветовая палитра и типографика), «движок» нумерологических расчётов, а также экраны анкеты, личного разбора и совета дня составляют базовую часть проекта. Настоящая глава сосредоточена на компонентной библиотеке интерфейса, экранах совместимости, важных дней и тарифов, реализации нижней навигации, интеграции приложения с мессенджером, подключении онлайн-оплаты и развёртывании на сервере. Прототипы экранов, выполненные в Figma, вынесены в приложение А к работе.
[145] {2|-} Описание чат-бота
[146] {-|-} Чат-бот «Подружка» представляет собой нумерологический сервис, функционирующий в мессенджере MAX. На основе даты рождения пользователя бот рассчитывает персональный профиль, включающий несколько числовых характеристик, сопровождает их текстовыми интерпретациями, определяет совместимость между людьми, ежедневно предоставляет «совет дня» и предлагает платные развёрнутые разборы. Данный бот послужил основой для разрабатываемого мини-приложения: приложение воспроизводит его расчёты и текстовые базы, поэтому понимание устройства бота необходимо для целостного описания проекта.
[147] {-|-} Взаимодействие с мессенджером осуществляется через официальную библиотеку MAX для разработки ботов. Веб-часть построена на фреймворке Express, который принимает входящие сообщения через механизм webhook. Данные хранятся в реляционной базе данных PostgreSQL, доступ к которой организован через ORM Prisma. Для формирования платных отчётов используется нейросетевая модель GigaChat. Постоянную работу программы обеспечивает менеджер процессов PM2, а входящие соединения и защищённый протокол — веб-сервер nginx.
[148] {-|-} Логически бот разделён на несколько частей: модуль обработки сообщений и команд, нумерологический движок, библиотека текстов-толкований, модуль платных разборов и оплаты, планировщик ежедневных рассылок и административный модуль.
[149] {-|-} Взаимодействие с ботом построено на командах и экранных меню с кнопками. При запуске регистрируются основные команды: /start, /menu, /me, /other, /compat, /advice, /full, /help. Для сбора данных в платных сценариях используется машина состояний (FSM): бот последовательно запрашивает имя, дату рождения, пол и характер отношений, запоминая промежуточные ответы.
[150] {-|-} Ядро бота — нумерологический движок, преобразующий дату рождения в набор чисел. Все значения приводятся к диапазону 1–22 (арканы) с помощью операции «свёртки»: если число превышает 22, цифры суммируются до получения значения не больше 22. На основе дня, месяца и года рождения вычисляются: число личности (из дня), число духовности (из месяца), число реализации (из суммы цифр года), число отношений (свёртка суммы трёх предыдущих), а также числа здоровья, энергии и миссии. Дополнительно рассчитываются производные показатели: число души, судьбы, характера и ресурса. Для сравнения людей предусмотрены формулы романтической, деловой и родственной совместимости. Алгоритм строго детерминирован: при одинаковой дате рождения результат всегда один и тот же. Корректность расчётов подтверждена при разработке мини-приложения, где движок был воспроизведён и сверен с ботом.
[151] {-|-} К каждому числу в боте подготовлены тексты-толкования. Для чисел от 1 до 22 хранятся отдельные наборы толкований по личности, реализации, отношениям, характеру контакта и практическим советам. При формировании разбора бот подбирает соответствующие тексты и собирает связное сообщение.
[152] {-|-} Бесплатный разбор показывает три главные зоны и подводит пользователя к платному отчёту, в котором раскрываются дополнительные темы: здоровье и энергия, деньги и реализация, любовь, повторяющиеся сценарии, слабые места, высшая миссия и практический план. Для платных отчётов используется GigaChat, который формирует более объёмные формулировки на основе рассчитанных чисел.
[153] {-|-} «Совет дня» рассчитывается на основе даты рождения и текущей даты: последовательно вычисляются личный год, месяц и день, приведённые к диапазону 1–22. По числу дня подбираются фокус, рекомендованные действия, предостережения и «действие на сегодня», а также определяются сферы жизни, для которых день особенно благоприятен. Совет дня доступен по запросу и рассылается автоматически через планировщик node-cron с учётом часового пояса. Предусмотрен механизм «догоняющей» рассылки и журналирование отправленных советов. Также бот находит ближайшие даты, «созвучные» числам человека, и для каждой формирует рекомендации по сферам жизни. Даты привязаны к опорным числам: день личной силы, день души, день жизненного пути, день личного роста, день материальной задачи.
[154] {-|-} Платные отчёты предлагаются по трём тарифам: разбор одного человека (89 ₽), разбор двух людей с совместимостью (149 ₽) и разбор окружения с «матрицей взаимоотношений» (499 ₽, в разработке). Оплата реализована через эквайринг Точка Банк: при выборе тарифа бот формирует заказ, создаёт платёжную ссылку и сохраняет сведения в БД. После оплаты бот проверяет подпись, находит заказ, сверяет сумму и отмечает его оплаченным, после чего продолжает сценарий сбора данных для отчёта.

[189] {2|-} Интеграция с мессенджером MAX и подключение оплаты 
[190] {-|-} Для работы внутри мессенджера к приложению подключён официальный клиентский скрипт MAX (Рисунок 2.10). Через него приложение сообщает мессенджеру о готовности, разворачивается на весь экран и получает данные пользователя, включая его идентификатор, необходимый для привязки оплаты. Обязательное условие работы mini-app — размещение по защищённому протоколу https [10, 11].
[191] {-|center|IMG} 
[192] {aa|-} Рисунок 2.10 – Подключение скрипта
[193] {-|-} Данный скрипт предоставляет глобальный объект window.WebApp, через который приложение взаимодействует с платформой. При инициализации приложение сообщает мессенджеру о готовности и разворачивается на весь экран. Через webApp.initDataUnsafe.user приложение получает данные авторизованного пользователя, включая его идентификатор и имя (Рисунок 2.11). 
[194] {-|center|IMG} 
[195] {aa|-} Рисунок 2.11 – Инициализация пользователя
[196] {-|-} Раздел «Тарифы» содержит платные подробные разборы. Сервис оплаты работает рядом с ботом, использует библиотеку @maxhub/max-bot-api для создания заказа и формирует персональную ссылку на оплату через интернет-эквайринг банка «Точка». API банка позволяет создать ссылку с привязкой к конкретному пользователю и сроком действия 7 дней. Полученная ссылка открывается в браузере или через встроенный механизм MAX. После успешной оплаты банк автоматически уведомляет бота, который подтверждает оплату в переписке и продолжает подготовку подробного разбора. Вынесение оплаты в отдельный сервис позволило подключить платежи, не внося изменений в действующего бота и не прерывая его работу [12].
[197] {2|-} Развёртывание приложения на сервере 
[198] {-|-} Готовое приложение размещено на сервере, доступном по адресу брибон.рф. Файл приложения помещён в каталог, который отдаёт бот, а распределением входящих запросов управляет веб-сервер nginx (nginx.org): страница приложения направляется к самому приложению, а запрос оплаты — к отдельному сервису оплаты; nginx также обеспечивает защищённое https-соединение. За стабильную работу программ (бота и сервиса оплаты) отвечает менеджер процессов PM2 (pm2.keymetrics.io), который поддерживает их запущенными и перезапускает при сбоях [10, 11].
[199] {-|-} Загрузка обновлённых файлов и управление сервером выполнялись по защищённому протоколу SSH с помощью программы PuTTY. При внесении изменений соблюдались меры предосторожности: перед заменой файлов создавались резервные копии, настройки веб-сервера проверялись специальной командой до их применения, а основной бот при доработках не останавливался [10, 11].
[200] {2|-} Тестирование и результаты  
[201] {-|-} По завершении разработки проведено тестирование. Проверена работоспособность экранов совместимости, разбора другого человека, важных дней и тарифов, а также нижней навигации и сквозных сценариев: переход от разбора другого человека к совместимости без повторного ввода данных, просмотр важных дней, запуск оплаты. Корректность расчётов совместимости и важных дней подтверждена сверкой с результатами бота. Отдельно проверено создание платёжного заказа: сервис оплаты успешно формирует персональную ссылку банка, при этом работа основного бота не нарушается. Приложение протестировано на мобильном разрешении экрана и внутри мессенджера MAX.
[202] {-|-} В результате реализованы компонентная библиотека интерфейса, экраны совместимости, важных дней и тарифов, нижняя навигация, а также выполнены интеграция приложения с мессенджером, подключение онлайн-оплаты и развёртывание на сервере. Совместно с базовой частью проекта это образует законченное мини-приложение, которое переводит возможности текстового бота в наглядный визуальный интерфейс и соответствует техническому заданию.
